# Daymark

Daymark is a desktop-only, full-stack calendar and task management app. Users
can register/log in, manage calendars and categories, create and edit events
(including recurring events, drag/resize, and a visual month view), and
manage tasks with priorities, statuses, and due dates — all backed by a
Spring Boot REST API with JWT authentication.

## Tech Stack

### Backend

- **Java 21** / **Spring Boot 3.3.4**
- **Spring Data JPA** (Hibernate) — `ddl-auto=validate` (schema is owned by Flyway, never generated by Hibernate)
- **PostgreSQL 16** (via Docker Compose)
- **Flyway** — versioned schema migrations
- **Spring Security** + **JJWT** — stateless JWT authentication
- **BCrypt** — password hashing
- **Bean Validation**
- **springdoc-openapi** — Swagger UI / OpenAPI docs
- **Lombok**
- **Maven**

### Frontend

- **React** (JavaScript, no TypeScript)
- **Vite**
- **React Router** — client-side routing and protected routes
- **Axios** — API calls, with a request interceptor for the JWT
- **FullCalendar** — visual month calendar with drag/resize

## Major Features

- User registration and login with JWT authentication
- Dashboard summarizing today's events, upcoming tasks, completed task
  count, and scheduled hours today
- Calendar and Category management (create, edit, delete)
- Event CRUD, including recurring events (`DAILY`/`WEEKLY`/`MONTHLY`)
- Visual month calendar (FullCalendar) with drag-to-move and
  resize-to-change-duration
- Task CRUD with priority, status, and due date, including inline status
  updates

## Running the Backend

1. Copy the environment template and fill in real values:

   ```bash
   cp .env.example .env
   ```

   `.env` is git-ignored and must never be committed.

2. Start PostgreSQL:

   ```bash
   docker compose up -d
   docker compose ps
   ```

3. Load the same variables from `.env` into your shell environment (Spring Boot does not read `.env` files automatically — only `docker compose` does). For example, in PowerShell:

   ```powershell
   Get-Content .env | Where-Object { $_ -match '^\s*[^#].*=' } | ForEach-Object {
       $parts = $_ -split '=', 2
       [System.Environment]::SetEnvironmentVariable($parts[0].Trim(), $parts[1].Trim(), "Process")
   }
   ```

   Or on macOS/Linux:

   ```bash
   set -a; source .env; set +a
   ```

4. Run the app:

   ```bash
   mvn spring-boot:run
   ```

## Testing

Backend unit tests (no Docker required):

```bash
mvn test
```

Backend integration tests (tagged `integration`, require PostgreSQL running and `.env` sourced into the environment — see above). They are excluded by default so `mvn test` never fails just because Docker isn't up:

```bash
mvn test -DexcludedGroups=
```

`PostgresIntegrationTests` verifies, against a real database, that:
- The Spring context starts and connects to PostgreSQL.
- Flyway applies `V1__init_schema.sql`.
- Hibernate's schema validation matches the migrated schema.
- All five JPA repositories (`User`, `Calendar`, `Category`, `Event`, `Task`) load and can query their tables.

Frontend build and lint:

```bash
cd frontend
npm run build
npm run lint
```

## Domain Model

- **User** — account with hashed password (BCrypt).
- **Calendar** — owned by a `User`; has a name and color.
- **Category** — owned by a `User`; used to tag/group events.
- **Event** — belongs to a `Calendar`, optionally a `Category`; supports recurrence (`NONE`, `DAILY`, `WEEKLY`, `MONTHLY`) and optional reminders. Recurring occurrences are generated on demand, never stored as individual rows.
- **Task** — belongs to a `User`; has a priority (`LOW`, `MEDIUM`, `HIGH`) and status (`TODO`, `IN_PROGRESS`, `COMPLETED`).

Schema is defined in `src/main/resources/db/migration/V1__init_schema.sql` and owned exclusively by Flyway.
